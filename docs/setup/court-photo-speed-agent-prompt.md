## 목표

주의: 사진 파일 다운로드·저장 자체는 건당 약 2초뿐이다. 나머지 약 6초는 법원 화면 이동(메인 재접속·공지·재검색)과 고정 대기다. 그러므로 화면 이동과 대기를 줄이는 것이 핵심이다.
법원 사이트에 대한 동시 접속(병렬 브라우저)을 늘리는 방식은 사용자 승인 없이 하지 않는다.

## 적용 절차 (현재 수집 중단 → 개선판으로 이어받기)
사용자는 수집이 끝날 때까지 기다리지 않고 지금 개선판으로 바꾸기를 원한다.
1. 수집기가 도는 동안: 코드 수정과 단위 테스트(`node --test scripts/court/*.test.mjs`)만 한다. 이 단계에서는 법원 사이트에 접속하지 않는다.
2. 준비되면 `data/court/standalone/STOP` 파일을 만들어 현재 수집기를 멈춘다. 수집기는 지금 물건을 마치고 미반영 사진을 DB에 반영한 뒤 종료한다.
3. Windows CIM으로 프로세스 종료를 확인하고, `running.lock`이 사라졌는지, 마지막 `sync-finish`가 completed이고 오류가 0인지 확인한다.
4. `STOP`을 삭제하고 개선판을 같은 체크포인트로 `--limit=10`만큼 실행한다. 완료된 물건을 건너뛰는지, 사건·물건 식별 검증과 사진 저장이 정상인지, 건당 시간이 얼마인지 `events.jsonl`로 확인한다.
5. 정상이면 `--limit=100000`으로 나머지 전체를 이어서 실행한다.
6. 문제가 있으면 수정 전 코드(git 기준 현재 버전)로 되돌려 같은 체크포인트에서 재개한다. 완료분은 보존된다.
7. 전환 시각, 전후 건당 시간, 검증 결과를 `ai-monitor-recovery.jsonl`과 handoff에 기록하고 사용자에게 한 번 보고한다.

## 절대 규칙
- 중지는 위 절차의 STOP 방식으로만 한다. 프로세스를 강제 종료하지 않는다. 실행 여부는 Windows CIM(`Get-CimInstance Win32_Process`) 명령줄로 확인한다.
- 기존 수집기와 개선판을 동시에 실행하지 않는다. 수집기가 도는 동안에는 별도 브라우저로 법원 사이트에 접속하지 않는다(동시 접속은 차단 위험이 있다).
- 403/429·보안문자·접근 차단·비활성 버튼은 우회·재시도 금지. 기존 `guard()`, 차단 감지, STOP 처리 유지.
- 병렬 브라우저/동시 탭 수집은 사용자 승인 없이 도입 금지.
- 사건번호·물건번호 일치 검증(다른 물건 사진 저장 방지) 약화 금지.
- `data/`, `.env.local`, 내부 handoff, 키는 Git에 넣지 말 것. 커밋·푸시는 사용자 승인 후.
- 사진은 물건당 최대 5장이면 충분(사용자 확인). 6장 이상을 찾기 위한 추가 탐색은 하지 않는다.

## 더 조사할 점 (측정으로 확정할 것)
1. 3.6초 구간 분해: `page.goto` 자체, 공지창 대기 4초 타임아웃이 실제로 몇 번 소진되는지, 공지 몇 개를 닫는지, 메뉴 클릭 후 법원 목록 로딩 시간. 필요하면 이벤트(`stage`)를 더 잘게 기록하는 계측만 먼저 추가.
2. 상세 화면에서 메인으로 가지 않고 검색 화면으로 돌아갈 방법이 있는지: 검색 폼이 DOM에 남아 있는지(WebSquare 탭/프레임 구조), 브라우저 뒤로가기, 검색 화면 w2xPath 직접 이동이 정상 동작하는지. 단, 공개 화면에서 사람이 할 수 있는 정상 조작만.
3. 검색 화면에 머문 상태에서 법원·사건번호만 바꿔 재검색할 수 있는지(메인·공지 반복 제거).
4. 고정 대기를 조건 대기로 바꿔도 안정성이 유지되는지(800/500/700ms). 각 대기가 왜 들어갔는지 git log·handoff에서 확인.
5. 사진 2.0초 구간 분해: 이미지 로딩 대기(`readAllOfficialPhotos`) vs 변환(`saveMedia`, webp 인코딩) vs manifest/results 파일 I/O.
6. 대상 정렬(같은 법원·같은 사건 묶기)로 아낄 수 있는 시간.

## 개선 후보 (우선순위 순, 측정 결과로 조정)
1. 메인 재진입·공지 처리를 사건마다 하지 않고, 검색 화면을 재사용하거나 검색 화면으로 바로 이동(가장 큰 3.6초 구간).
2. 같은 사건 안의 다음 물건은 재검색 없이 처리(상세→검색결과 복귀 방법이 확인될 때).
3. 고정 `delay`를 화면 조건 대기로 교체.
4. manifest를 메모리에 캐시하고 results 파일 쓰기를 줄임(체크포인트 안전성은 유지: 중단 시 완료 물건 재처리 없음).
5. (사용자 승인 필요) 병렬 처리는 차단 위험 때문에 제안만 하고 구현하지 말 것.
