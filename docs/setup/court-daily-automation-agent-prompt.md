# 법원 사진 + 국토부 실거래가 일일 자동화 — 에이전트 지시서

작업 폴더: `C:\Users\hjdh5\Desktop\auction-deal-finder`
선행 작업: `docs/setup/court-photo-speed-agent-prompt.md`(속도 개선)를 먼저 끝낸 뒤 진행. 두 작업 모두 `scripts/court/case-repair.mjs` 계열을 고치므로 동시에 하지 말 것.

## 목표
매일 사람 개입 없이 법원 물건 정보·사진, 국토부 실거래가 매칭, DB 반영, 공개 사이트 배포가 끝나게 한다.
반복 작업은 스크립트가 하고, AI는 이상이 생겼을 때만 개입한다(5분마다 AI가 파일을 읽는 방식 폐지).

## 사용자 결정 사항 (2026-10-10)
1. **매일 오후 3시(KST)** 자동 실행. 기존 오전 9시 예약은 이 일정으로 대체.
   - 현재 진행 중인 6,383건 전체 사진 재확인이 끝난 뒤부터 적용. 그 전에 시작해 중복 실행하지 말 것.
   - 신규 법원 목록 수집도 이 일일 실행에 포함해 재개.
2. **국토부 하루 요청 한도 10,000회**(data.go.kr 개발계정 한도). `.env.local`의 `MOLIT_DAILY_REQUEST_BUDGET`과 기본값을 10000으로.
3. **국토부 429(요청 과다)/거부 시 자동 처리**: 그날은 중단하고 `molit-access-paused.json` 기록 → **다음 날(KST) 실행 때 자동으로 1회 재개 시도**. 재개 후에도 다시 거부되면 다시 다음 날까지 대기하고, **연속 3일** 거부되면 사용자에게 알림(키 만료·한도 문제 가능성). 사용자가 직접 풀어야 하는 구조는 금지.
4. **사진은 물건당 5장이면 충분.** 6장 이상을 찾기 위한 추가 탐색 불필요.
5. 보고는 **이상이 있을 때와 매일 실행 완료 요약만**. 정상 진행 중 보고 불필요.

## 일일 실행 순서 (하나의 실행 스크립트, Windows 작업 스케줄러 등록)
1. 실행 중복 확인(`running.lock` + Windows CIM 프로세스), STOP 파일 존중.
2. **법원 목록·상태 갱신**: 서울·경기 16개 법원의 물건 목록 변경(신규·매각·유찰·취하·기일 변경)을 확인. 모든 진행 중 물건의 상태 정보는 매일 갱신 대상.
3. **사진 수집**:
   - 대상 = 신규 물건 + 저장 사진이 5장 미만이고 아직 "법원 사진 미제공"으로 확인되지 않은 물건 + 이전 실행에서 실패한 물건.
   - 이미 5장을 저장한 물건은 **사진만** 다시 받지 않는다(물건 상태 정보는 2단계에서 계속 갱신).
   - "상세 비활성/사진 미제공"으로 확인된 물건은 매일 말고 주 1회 재확인(나중에 공개될 수 있음).
4. **국토부 실거래가**: 경매 대상 아파트가 있는 지역코드만 조회. 이번 달·지난달은 매일 새로 받고, 그보다 오래된 달은 7일 캐시 재사용. 요청 간 간격 유지(현재 1.1초). 한도 10,000회.
5. **DB 반영** 후 실제 DB 읽기로 개수 검증.
6. **공개 사이트 배포**: 정상 사진 파일과 공개 데이터만 커밋·푸시(GitHub Pages). `.env.local`, `data/`, 내부 handoff, 키는 절대 제외.
7. 실행 요약 저장: 신규 물건, 상태 변경, 신규 사진/총 사진/미제공/실패, 국토부 요청 수/매칭 수, DB 오류, 배포 결과.

## 이상 감지 (스크립트로, AI 아님)
기존 `scripts/court/monitor.mjs`, `health.json`, `windows-notify.mjs`를 활용.
- 이상 기준: 실행 중인데 `events.jsonl`에 10분 넘게 새 처리 기록 없음 / 프로세스 사라짐 / 상태가 blocked·error / DB 반영 실패 / 오후 3시 실행이 시작되지 않음 / 배포 실패.
- 이상 시 Windows 알림 즉시, 해결 안 되면 **30분마다 재알림**(조용히 멈춰 있는 상태 금지 — 과거 4시간 정지 사례).
- 일시적 오류(타임아웃 등)는 기존 `navigation-recovery`/`readiness-recovery` 범위 안에서 자동 복구, 같은 체크포인트로 재개(완료 물건 건너뜀).
- 법원 403/429·보안문자·접근 차단은 우회·재시도 금지 → 그날 중단, 다음 날 정상 실행 때 다시 시도, 연속 2일이면 사용자 알림.

## 정리할 것
- 다른 앱에 있는 기존 AI 감시 작업(automation-2, 5분 보고)은 이 자동화가 검증되면 삭제.
- 기존 규칙 중 "원인 변경 없는 재시작 금지 + 같은 장애 중복 통지 금지"가 겹쳐 멈춘 채 방치된 사례가 있었음. 새 규칙은 위 "이상 감지"를 따른다.
