## 3. 실거래 매칭

- 수집 후 파이프라인에서 국토부를 다시 조회한다. '실시간'은 원천 신고자료를 갱신 시 조회한다는 의미이며 실시간 거래 체결 피드는 아니다.
- 같은 단지·법정동·지번 + 전용면적 차이 0.1㎡ 이하의 검증 규칙부터 사용. 동 일치는 강제하지 않고 층·동 차이를 공개한다. 다른 면적 거래를 섞어 할인율을 만들지 않는다.
- 행정안전부 공식 화면에서 서울 25개 구, 경기 시·군·구 코드 카탈로그를 확보했다(`scripts/court/regions.json`). 구가 있는 시의 부모 코드를 임의 조회에 쓰지 않는다. 모든 지역의 실거래 API 응답 검증을 마쳤다는 뜻은 아니다.
- 남양주 API 응답에서 읍·리 전체 명칭을 확인해 주소 매칭을 보강했다. 지역별 조회 XML과 계약일·면적·층·지번 근거를 보존한다.
- 다음: 아파트 유사 면적 후보 표시(직접 비교와 구분), 오피스텔·연립/다세대 동일 건물 비교, 단독·다가구/상가/토지는 거리·용도·면적·연식 조건을 갖춘 인근 참고 거래. 근거가 없으면 시세를 생성하지 않는다.

## 4. 사용자 화면

- 이미 구현된 사진·공식 출처·상태/확인시각·실거래 원문·대상과 차이를 실제 물건으로 검증한다.
- 다음: 서울·경기 기본 검색 범위, 사진/상세/상태/비교 단계별 준비 상황, 매칭 불가 사유와 마지막 조회 시각을 목록에도 표시.
- 서울·경기 기본 검색 범위 적용 완료(6,199건). '모든 지역' 선택으로 기존 전국 자료를 볼 수 있다. 목록 단계별 준비 상황은 후속 구현이다.
- 비교의 '거래 없음', '지역 미지원', '면적 미확인', '조회 실패'를 명확히 구분한다.
- 지도와 주변 참고 매물은 이 흐름 안정화 후 연결한다. 호가와 실거래는 분리한다.
