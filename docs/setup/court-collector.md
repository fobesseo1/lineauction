## 이번에 해결한 실제 화면 문제

- **10페이지 이후 이동:** 화면에 있는 다음 목록·이전 목록 버튼을 사용한다. 마지막 페이지 버튼으로 끝을 직접 확인하며 총 건수만으로 페이지 수를 추측하지 않는다.
- **마지막 페이지의 숨겨진 행:** WebSquare는 이전 페이지 행을 숨겨서 남긴다. 보이는 행만 읽어 마지막 페이지의 실제 4건만 저장한다.
- **페이지 경계의 일괄매각:** 8개 물건이 두 페이지에 걸쳤다. 바로 이어지는 페이지 경계에서 식별번호·가격·기일·상태가 일치하고 자산 원문이 서로 다를 때만 합친다. 같은 원문 페이지 반복이나 서로 다른 가격을 임의로 합치지 않는다.
- **열리지 않는 토지 주소 링크:** `2023타경111613 / 물건1`은 토지 링크로 상세가 열리지 않았으나 같은 물건의 건물 주소 링크로 열렸다. 표시된 대체 주소로 두 번째 시도에 성공하는 것을 확인했다.
- **상세 복귀 시점:** 목록과 페이지 버튼이 실제 보이는 상태로 돌아온 뒤 다음 물건을 처리한다.
- **상세 실패 격리·재개:** 목록은 보존하고 해당 상세만 실패/대기로 남긴다. 18건을 작은 묶음으로 나눠 저장하고 미완료 키만 넘겨 최종 완료했다. 긴 작업 전체를 한 번의 브라우저 호출에 넣지 않는다.
- **부분 수집의 자산 손실 방지:** 부분 범위가 일괄매각 중간에서 시작해도 이전에 확인한 토지·건물을 삭제하지 않는다. 전체 목록을 재확인한 경우에 자산 구성을 교체한다.

## 저장 구조와 명령

- `scripts/court/browser.mjs`: 공식 화면 이동·목록·상세 수집. 문서화된 CUA 브라우저 API 사용.
- `scripts/court/core.mjs`: 식별·검증·페이지 경계 병합·면적 추출·변경 비교·상세 대기열.
- `scripts/court/store.mjs`: 원문·실행 보고서·현재 상태 저장. 검증에 실패해도 원문과 거절 사유를 남기고 정상 상태 유지.
- `scripts/court/cli.mjs`: 로컬 수신·원문 재처리·다음 상세 작업 조회.
- `scripts/court/fixtures/`: 실제 수집한 표본 원문을 이용한 회귀 테스트 자료. 최신 정보로 사용하지 않는다.

```powershell
npm run court:receive
npm run court:import -- <raw.json>
node scripts/court/cli.mjs queue
npm run court:test
```

수신기는 `http://127.0.0.1:3001`에서만 실행한다. CUA로 원문 JSON 입력란을 채워 저장하며 사용자에게 복사·입력을 요구하지 않는다. 작업 후 수신기를 종료한다.

- 현재 상태: `data/court/current.json`
- 실행별 원문·보고서: `data/court/runs/<실행ID>/{raw,report}.json`
- 새 파서로 원문 이력을 순서대로 재검증한 기록: `data/court/replays/replay-2026-10-07.json`

`data/court`는 Git에서 제외한다. 현재 파일 저장은 단일 작업에서 순차 실행한다. 부분 실행의 보고서는 해당 실행만의 범위이며, 이전에 수집한 전체 목록이 삭제되었다는 의미가 아니다.

## 브라우저 수집 함수 사용

공식 홈페이지에서 원하는 법원의 **추가 조건 없는 기본 검색** 목록을 연다. `node scripts/court/cli.mjs browser-source`의 함수를 CUA 실행 환경에 직접 정의하고, 연결된 탭을 전달한다. 문자열 eval이나 별도 브라우저 설치는 필요하지 않다.

```js
// 전체 목록만 수집. 한 호출에서 최대 100페이지까지 제한.
const listRun = await collectCourtPages(courtTab, {
  court: '서울중앙지방법원', startPage: 1, maxPages: 100, detailCases: [],
});

// 상세는 기본 최대 4건. 나머지 작업은 pending으로 저장.
const detailRun = await collectCourtPages(courtTab, {
  court: '서울중앙지방법원', startPage: 3, maxPages: 2, maxDetails: 4,
});

// 재개: 직전 실행의 미완료 키 또는 저장된 상세 대기열을 전달.
const next = await collectCourtPages(courtTab, {
  court: '서울중앙지방법원', startPage: 3, maxPages: 2,
  onlyDetailKeys: detailRun.retryDetailKeys, maxDetails: 4,
});
```

`pagination.nextPage`는 이어서 읽을 페이지를 나타낸다. 목록 오류가 난 경우 해당 페이지부터 재시도한다. 상세는 `detailJobs`에서 성공·실패·대기와 시도 횟수를 구별하고, 영구 상태의 `detailQueue`에 미완료 작업을 보존한다. 완료된 상세를 수집하지 않는 경우에는 기존 상세와 그 관측 시각을 유지한다.
